# 결정 기록

## 2026-10-16

- 문제: 작업 폴더에 기존 프로젝트와 원본 자산이 없음.
  선택: 정적 HTML/CSS/JavaScript와 자산 설정 파일로 시작.
  이유: 설치와 빌드 부담을 줄이고 JavaScript 학습에 활용.
  결과: 로컬 서버만으로 실행 가능. 원본 연결 전 편집은 비활성화.

- 문제: 원본의 비율·투명 영역·해상도를 알 수 없음.
  선택: 임의 프레임과 사진 좌표를 만들지 않음.
  이유: 전달된 프레임 우선 사용 요구를 지킴.
  결과: 원본 수신 후 실제 구조 확인이 다음 필수 작업.

- 문제: 미리보기와 출력의 위치가 달라질 수 있음.
  선택: 동일한 원본 픽셀 좌표와 캔버스 그리기 함수 사용.
  이유: 화면 크기와 무관한 합성 기준이 필요함.
  결과: 편집 테두리는 별도 HTML 요소로 표시해 PNG에서 제외.

- 문제: 웹과 현장 체험의 관계를 오해할 수 있음.
  선택: 하단에 개인 제작·현장 부스 비연동 명시.
  이유: 이용 방식과 책임 범위를 정확히 전달.
  결과: 공식 홈페이지는 새 탭으로 안내. 사진 전송·인쇄 기능 없음.

## 자산 연결

- 문제: 네 종류의 프레임과 스티커 7종을 전달받음.
  선택: 기본 범위의 고정 배치에 맞춰 세로 검정 한 종류를 사용하고 스티커 7종 연결.
  이유: 프레임 선택 기능 추가보다 사진 조정·저장 검증을 우선.
  결과: 다른 프레임 원본도 보관. 스티커는 config.json 목록만으로 확장 가능.

- 문제: 첨부 미리보기의 흰 사진 칸이 실제 투명 영역인지 확인 필요.
  선택: 원본 PNG 알파 채널과 픽셀 경계 조사.
  이유: 축소된 첨부 화면으로 좌표를 추정하면 출력이 어긋남.
  결과: 원본 1500×2250, 칸 시작 x=89/764, y=121/1119. 사진 영역 648×971로 알파 경계까지 덮음.

## 프레임 4종 선택 추가
- 문제: 사용자가 다른 세 종류도 사용할 수 있도록 요청.
  선택: 원본 4종을 선택 메뉴로 제공하고 프레임마다 별도의 사진 좌표 사용.
  이유: 가로 하양은 가로 검정과 사진 칸 좌표가 조금 달라 각각 측정해야 함.
  결과: 사진 확대율 유지, 이동량과 스티커 중심은 새 크기에 맞춰 환산. 로딩 실패 시 기존 프레임 유지.

## 스티커 추가·선택 박스 크기 조절
- 문제: 사용자가 SVG 5종 추가, 색상/방향 순서의 프레임명, 슬라이더 대신 선택 박스를 요청.
  선택: 스티커 목록을 12종으로 확장. 프레임명은 검정 / 세로 등으로 변경. 선택 테두리에 모서리 4개를 두고 슬라이더 제거.
  이유: 대상 위에서 위치와 크기를 직접 조작할 수 있도록 함. 44px 터치 영역과 키보드 크기 조절도 제공.
  결과: 스티커는 비율과 반대 모서리를 유지하며 조절. 사진은 고정된 사진 칸 안에서 확대·축소하고 최소 채우기 크기 이하로 줄이지 않음. 선택 박스는 HTML로 표시해 PNG에 포함되지 않음.

## 스티커 순서·사진 추가 동선 수정
- 문제: 겹친 스티커를 선택하면 앞으로 표시하고 사진 칸 안에서 바로 업로드하고 싶다는 요청.
  선택: 마지막 선택 순번을 스티커에 기록해 캔버스와 조작 영역에 같은 순서 적용. 빈 사진 칸 중앙에 48px + 표시, 별도 번호별 업로드 버튼 제거.
  이유: 드래그 도중 DOM을 재생성하지 않고 표시 순서만 바꿔 조작을 유지. 업로드 위치와 사진 칸을 직접 연결.
  결과: 선택한 스티커는 출력에서도 앞으로 오며 사진이 들어간 칸은 +를 숨김. 사진 선택 후 교체 버튼은 유지.

## 프레임 안에서 사진·스티커 바로 편집
- 문제: 별도 사진 구역이 불필요하고, 스티커 삭제가 편집 대상에서 멀리 떨어져 있음.
  선택: 사진 메뉴와 사진 도구 구역을 제거. 사진과 스티커를 직접 눌러 조작 대상을 전환. 업로드한 사진 오른쪽 위에 ×, 선택한 스티커 가까이에 삭제 버튼 표시.
  이유: 메뉴 이동과 스크롤 없이 사진 추가·삭제와 스티커 크기 조절·삭제를 진행할 수 있음.
  결과: 사진 삭제 시 해당 칸이 +로 복구. 사진 ×는 스티커 선택 중에도 사용 가능. 사진 오른쪽 위는 삭제에 쓰고 나머지 세 모서리로 크기 조절. 스티커 삭제 버튼은 선택 박스를 따라 이동하며 화면 안에 배치.

## 화면 문구·아이콘 간소화
- 문제: 사진 추가·삭제 표시와 안내 문구가 많고 스티커 목록이 길다는 요청.
  선택: +의 원형 배경 제거, 사진 × 시각 크기 24px로 축소(터치 영역 44px 유지), 지정 안내 문구 제거, 최근 정상 상태 문장은 화면에서 숨김. 스티커 3열 배치.
  이유: 시각적 부담과 스크롤을 줄이면서 터치 조작성을 유지.
  결과: 사진 부족·실패 안내만 필요할 때 화면에 표시. 일반 상태는 접근성 안내로만 제공.

## GitHub Pages 배포 준비
- 문제: 개발 기록은 저장소에 보관하면서 로컬 캡처와 불필요한 파일은 공개하지 않아야 함.
  선택: JPG/JPEG·macOS 파일·비밀 설정·생성물을 .gitignore로 제외. 별도 스크립트로 웹 파일 3개와 공개 assets만 _site에 복사. Actions는 main 브랜치 수동 실행만 배포.
  이유: 저장소 보관 범위와 실제 웹 배포 범위를 명확히 구분하고, 업로드만으로 사이트가 공개되지 않도록 함.
  결과: 기존 기능 파일은 변경하지 않음. docs Markdown 기록은 유지하고 로컬 JPG도 삭제하지 않음. README에 준비·실행·향후 GitHub 절차 정리.
